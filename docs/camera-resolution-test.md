# Issue #3：無音撮影の解像度検証

このページは、教室の後方から板書が読めるかをiPhoneで確かめる試作です。
可読性・シャッター音・ホーム画面での動作は実機の結果で判断します。
結果が出るまでは設計書7章の未決事項を変更しません。

## 開き方

mainへのマージ後、Pages公開の成功を確認してから、iPhoneのSafariで
<https://yukito04161020-design.github.io/bansho-camera/> を開きます。
共有メニューから「ホーム画面に追加」し、そのアイコンで起動して、
「カメラの解像度を検証する」を選びます。
ホーム画面に追加済みの場合はアプリを閉じて開き直してください。

直接開くURLは
<https://yukito04161020-design.github.io/bansho-camera/camera-test.html> です。
ホーム画面用manifestの起動先はトップページなので、トップページからの追加を推奨します。

## 要求する解像度

最初の`getUserMedia`では以下を渡します。

```js
{
  audio: false,
  video: {
    facingMode: { exact: "environment" },
    width: { ideal: 7680 },
    height: { ideal: 4320 },
    resizeMode: { ideal: "none" }
  }
}
```

高い希望値を指定し、取得できる範囲の高解像度を求めます。
映像トラックの`getCapabilities()`が利用できる場合は、幅・高さの`max`を
それぞれ`ideal`として`applyConstraints`で再要求します。
能力値の取得・再要求が失敗した場合は、最初の映像を維持します。
`resizeMode`は対応するブラウザでのクロップ・リサイズを避ける希望値です。

幅・高さは必須値ではありません。能力値の幅と高さの上限が同時に実現できるとは限らず、
機種・カメラ・ブラウザによって実際の解像度は変わります。
「要求」の表示は要求値、「映像」の表示は`videoWidth`・`videoHeight`で取得した実寸です。
実機結果には必ず「映像」の値を記録してください。
向きの情報が取得できない場合は画面に案内が出るので、映像が背面カメラか確認してください。

## iPhoneでの確認手順

1. ホーム画面のアイコンから試作を開く。Safariのツールバーが表示されないことを確認する。
2. 「カメラを開始」を押し、カメラを許可する。背面の映像が表示されることを確認する。
   マイクの許可は要求しない。拒否した場合は、画面の案内に従ってSafari/iPhoneの設定で許可して再試行する。
3. 「映像：幅 × 高さ px」を記録する。縦向き・横向きそれぞれで表示と撮影が動くことも確認する。
4. 教室の後方の普段使う席から、板面全体を映像に収めて「1コマを撮影」を押す。
   シャッター音が鳴らないことを確認する。
5. 「撮影画像」のサイズが撮影した映像サイズと一致することを確認する。
   「等倍で確認」を押し、上下左右にスクロールして小さな文字が読めるか確認する。
   「画面に合わせる」で全体表示へ戻る。ブラウザのピンチ操作も禁止していない。
6. 「カメラに戻る」で次の撮影を行う。黒板・ホワイトボード・スクリーンをそれぞれ確認する。
7. アプリを裏に回し、再び開く。「カメラを開始」で再開できることを確認する。
   裏に回ったとき・停止したとき・画像確認中はカメラを解放する。
8. 撮影画面の「自動消灯を防止しています。」を確認する。
   Wake Lockが非対応・拒否・解除された場合は案内を表示するので、確認中に画面が消えないかも記録する。

画像はcanvasに表示するだけで、保存・送信は行いません。
「カメラに戻る」やページを閉じる操作で画像は失われます。
板書の画像を公開リポジトリやIssue/PRへ添付しないでください。

## 自動で確認する部分

`npm test`で、背面・解像度の要求、能力値が使えない場合のフォールバック、
カメラ取得失敗時の解放、実寸のフレーム切り出し、未準備時の撮影防止を確認します。
カメラAPIは偽物を使い、板書の画像をテストに追加しません。
版番号とアプリの更新の仕組みはIssue #4で扱います。
